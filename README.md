# Derivation Mechanisms

The central home for the **methods** used to create everything in the Tepenian universe and the author's other worlds: characters and their arcs, locations from a single building to a nation, cultures, stories, quests, game systems, and the research that feeds them.

A mechanism here is a *way of producing* something: a methodology, a runbook, a template, a research protocol, a design framework, or a reference set that those methods draw on. It is written to apply everywhere, in every project and medium (games, novels, TV, film), rather than to one book or one game.

## What this repo is not
- **Not canon.** Nothing here says what *is* true in any world. Canon lives in the [Tepenian Universe Timeline](https://github.com/TerranLights/TepenianUniverseTimeline) and in each project's own repo.
- **Not results.** A method lives here; what it produces lives elsewhere. For example, the Deep Culture Investigation's *method* is in `Environment/DCI [Deep Culture Investigation]/`, while its *results* are in the [Culture Library](https://github.com/TerranLights/CultureLibrary).
- **Not the universal design laws.** The laws that bind every character, location, object and event (for example, no national stereotypes) are kept with the canon in the Timeline repo's `Universal Design Laws/`. A *binding mechanism* (for example, "the Enneagram is the starting point, not the result") is filed here.

## How it works
- **One version of each mechanism.** Where copies of the same method had drifted apart across projects, they were combined into one: whatever one copy had that the others lacked was folded in.
- **Disagreements stay visible.** Where versions contradict each other, the file keeps both readings, marked **⚠️ Versions differ**, and every case is listed in `OPEN DECISIONS - Versions Differ (2026-10-30).md` for the author to settle.
- **Provenance is recorded once.** No file says which project it came from; `SYNC_RECORD.md` holds that record (and `SYNC_REPORT_2026-10-31.md` the report of the first sync).
- **Methods are developed here.** When a mechanism changes, it is changed in this repo; the projects that use it point here.

## What's inside

| Folder | What it holds |
|---|---|
| `Characters/` | **Character Development Methodology**, a complete system for developing any character from a first idea onward; **Enneagram**, the type files every character starts from (adjusted to the character, never copied as is); **Robot-specific** material, such as robot universals and doll-height transposition |
| `Environment/` | Location and culture methods: the **ULM** (Universal Location Methodology, for any location that is not a Concordia district); the **Concordia District Method**; **CST** (Cultural Synthesis Techniques) and **RWBEM** (Real-World Basis Extrapolation Method), which follow the ULM; the **DCI** (Deep Culture Investigation: how each culture-nation understands every concept); **OOLSD** (Object-Oriented Location Synthesis and Derivation, for structures, vessels and orbital and off-world locations); the **Local Robot Culture** method; the **Neo-Races and Cultures** method; the **Nation Drawing** method; and templates for city specs, city cultures and nation profiles |
| `Stories/` | **Story Structure**, the author's composite structure and the frameworks it draws on; **Plot Constraints**, the Plot Constraint Mapping method (what each beat must and must not be, for any linear medium; not for games); **Quest Design** (main, DLC and district questlines, lore, secret endings, build templates); **Historical Vignettes**; **Continuity** guidelines; and story templates (character arcs, background notes, a development road map) |
| `Processes/` | **Canon Gap Resolution**, for filling holes in canon without contradicting it; and **Research Protocols**, the briefs and dispatch templates for real-world research rounds |
| `Game_Design/` | Design principles, the perk framework, the forbidden-trait design method, and *What Is Fun?*, the author's theory of fun and the research behind it |
| `Data_Reference/` | Reference sets the methods draw on, such as the **Symbolism** framework |
| `Glossary/` | Definitions of essentially every term any of the repos needs: organizations, megacorporations, substances, technologies and coined words, one file per letter, with a category index |

Start with a folder's `README.md`, `00_RUNBOOK.md` or `00 - README.md` where it has one.
